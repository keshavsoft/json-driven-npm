# Declarative TypeScript Generation from JSON

[**View this document as HTML**](./dts-generation.html) · [**Documentation Hub**](./index.html)

A common concern with dynamic, in-memory client architectures is typing: *If endpoints are dynamically mounted at runtime from JSON, how do consumers get full IDE autocomplete and static type safety?*

In this architecture, typing is **declarative and automated**: because `api.json` and `source.json` form a complete, unambiguous contract of the client API, TypeScript declarations (`src/index.d.ts`) are generated deterministically directly from the JSON files.

---

## The Generation Pipeline

```text
api.json (Allowed Route Paths)  +  source.json (Domain Spec & Descriptions)
                          │
                          ▼
             Contract Scanning & AST Tree Assembly
                          │
                          ▼
             TypeScript Declaration Generator
                          │
                          ▼
                   src/index.d.ts
    (Full IDE autocomplete, hover tooltips, & compile-time types)
```

---

## How Declarative Typing Works

### 1. Contract Alignment
The generator scans the active version in `src/index.js` (e.g. `src/v3/index.js`) and cross-references `api.json` against `source.json`:
- Every path declared in `api.json` (such as `"app.founder.profile.fetch"`) is verified to exist in `source.json`.
- Any mismatch or missing specification halts the build immediately, preventing "ghost" endpoints.

### 2. JSDoc Extraction
Each endpoint specification in `source.json` includes a human-readable `"description"`. The generator extracts this description and injects it as a native JSDoc comment above the method signature in the generated type definition.

### 3. Generated Declaration (`src/index.d.ts`)

For `src/v3`, the resulting declaration file is clean and exact:

```typescript
/**
 * Generated from src/v3.
 * Do not edit this file directly.
 */

export type AppApi = {
    founder: {
        profile: {
            /** Fetches founder and software architect profile. */
            fetch: (inParam: string, ...inArgs: any[]) => Promise<any>;
        };
        links: {
            /** Fetches official website, GitHub, NPM, and LinkedIn profile links. */
            fetch: (inParam: string, ...inArgs: any[]) => Promise<any>;
        };
    };
    company: {
        info: {
            /** Fetches KeshavSoft organization information and engineering philosophy. */
            fetch: (inParam: string, ...inArgs: any[]) => Promise<any>;
        };
    };
    ecosystem: {
        packages: {
            /** Lists flagship packages in the KeshavSoft ecosystem. */
            fetch: (inParam: string, ...inArgs: any[]) => Promise<any>;
        };
    };
};

declare const app: AppApi;

export default app;
```

## Developer Experience

When a consumer imports `json-driven-npm` in their project:

```typescript
import app from "json-driven-npm";

const profile = await app.founder.profile.fetch();
```

1. **IntelliSense Autocomplete:** Typing `app.` instantly displays `founder`, `company`, and `ecosystem`.
2. **Hover Documentation:** Hovering over `.profile.fetch` displays the exact description from `source.json`.
3. **Type Safety:** Attempting to call an unexposed route (`app.users.delete()`) fails at compile-time with a TypeScript error.

---

## Running Type Generation

Generate declarations directly via `create-intellisense`:

```bash
# Generate declarations from the active version
npx create-intellisense

# Or run type generation and execute test suite
npm run verify
```

Declarations remain in lockstep with JSON contracts at all times.

---

## Applying This to Your Own Custom Packages

Once you understand how `json-driven-npm` declares its API in JSON:

1. **Create your contracts**: Define your own endpoints in `source.json` (or `structure.json`) and your public allowed paths in `api.json`.
2. **Install the companion tool**: Add [`create-intellisense`](https://www.npmjs.com/package/create-intellisense) as a devDependency:
   ```bash
   npm install -D create-intellisense
   ```
3. **Automate in your scripts**:
   ```json
   "scripts": {
       "test": "node --test test/test.js",
       "verify": "create-intellisense && npm test"
   }
   ```
4. **Instant TypeScript autocomplete**: Running `create-intellisense` scans your JSON contracts and generates your package's `index.d.ts` automatically!
