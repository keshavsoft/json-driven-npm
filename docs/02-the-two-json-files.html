JSON-DRIVEN NPM · FIELD GUIDE 02/07

The two JSON files

One file controls access; the other describes the endpoint.

The two JSON files answer different questions. Keeping those questions separate makes the public API easy to review and the endpoint definitions easy to maintain.

api.json

What is exposed?

[
  "app.founder.profile.fetch",
  "app.company.info.fetch"
]

This is the allowlist. Only listed paths are mounted into the public client tree.

source.json

What does it describe?

{
  "app": {
    "founder": {
      "profile": {
        "fetch": {
          "action": "fetch",
          "resource": "profile",
          "data": {}
        }
      }
    }
  }
}

This holds endpoint metadata and, in this reference package, sample response data.

Remember

A path in source.json is not automatically public. It must also appear in api.json.
