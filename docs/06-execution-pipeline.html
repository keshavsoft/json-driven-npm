The execution pipeline

Three small jobs, performed in order.

The executor coordinates the work. Each module has one responsibility: normalize the input, find the endpoint definition, and dispatch the result.

Step 1 · validateInput.jsNormalizes the first input parameter. Missing values become an empty string; non-string values are converted to strings; strings are trimmed.
Step 2 · getEndpointSpec.jsSplits the dot path and reduces through source.json to find the endpoint definition.
Step 3 · dispatchMock.jsReturns endpoint.data when present. Otherwise, it returns a structured mock response using endpoint metadata and arguments.

Important today

The current dispatcher is a mock/data dispatcher. It does not make a real HTTP request. A transport implementation would be a deliberate extension to this layer.

Remember

The pipeline is intentionally centralized. A change to dispatch behavior can be made without creating a separate executor for every endpoint.
