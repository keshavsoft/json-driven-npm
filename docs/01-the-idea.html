JSON-DRIVEN NPM · FIELD GUIDE 01/07

The idea

Why make endpoints data?

Imagine a client library with 100 endpoints. A traditional approach can create many folders and small files that all repeat the same pattern. This project moves the endpoint list and endpoint descriptions into JSON, then assembles the callable API object at startup.

Traditional approach

users/profile/fetch.js
users/settings/fetch.js
reports/summary/fetch.js
reports/metrics/fetch.js

Each endpoint can bring another file and another repeated wrapper.

JSON-driven approach

api.json       → which paths are public?
source.json    → what does each path describe?
route engine   → build callable functions in memory

Endpoints become data. Shared code handles the repeated mechanics.

Remember

The goal is not to remove JavaScript. The goal is to stop writing nearly identical JavaScript for every endpoint.
